全文索引热路径优化：实现与验证报告

结论：编译和已执行正确性回归通过；性能未证明有效提升，当前补丁仅应视为候选实现。
本轮遵循先完成内核代码与回归用例、再统一评测的顺序。评测期间仅修正测试字符集与实例支持范围的匹配，未修改内核代码。

修改范围：
1. IK 字符分类仅解码一次，保持原有分类优先级和 UTF16 代理项判断。
2. IK 复用已读取的字符、长度与类型，直接调用各处理器，保留处理顺序。
3. 英文分词为 UTF8 ASCII 字节直接返回长度 1，其他字符保留原有多字节函数；分隔符判定合并同一 ctype 表的位掩码。
依据为静态代码路径中的重复计算；未采集 CPU profile，因此不宣称已定位主导耗时瓶颈。

正确性：488 个完整分词 JSON 用例和 240 组完整 MATCH/LIMIT 结果与原版一致。
比较内容包含 token 顺序、词频、返回行 ID、8 位小数相关性得分、确定性 LIMIT 排序。
覆盖 IK 默认/smart、BENG、SPACE、中日韩文、ASCII 控制字符/NUL、全角、emoji、大小写、重复词、长输入、固定种子随机输入。
覆盖索引创建、UPDATE/DELETE/INSERT、索引删除重建，utf8mb4_general_ci 与 utf8mb4_bin。
实例仅支持 utf8mb4/binary。未执行全库回归或独立内存检测器；有限回归不能证明所有输入均正确。

评测环境：36.150.116.206:35084，独立 SQL 端口 32851 / RPC 32852。
容器配额 16 CPU、55 GiB；测试实例 memory_budget=16G，datafile_size=4G，maxsize=8G，log_disk_size=2G。
编译：RelWithDebInfo，clang++-17，-O2；cmake --build build_release --target seekdb -j8。
原版与优化版使用同一源码树和构建配置；复用既有构建缓存。
源码目录：/workspace/seekdb/file-sql-validation；验证目录：/workspace/seekdb/fts-hotpath-validation。
保存原版二进制后仅同步本轮三个内核文件及回归测试；未改变已有 File SQL 修改。
